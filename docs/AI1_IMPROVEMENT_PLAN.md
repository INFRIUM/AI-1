# AI① 이상탐지 개선 실험 계획 (실행 전 고정)

작성일: 2026-11-23 · 작성: AI①

## 1. 목적과 데이터
- 기존 v1·v2가 손상을 대부분 놓친다 (HBTA 열화본 상태별 탐지 v1 0–5%, v2 0–33%). 다른 구조물에도 쓸 방법을 **하나** 고른다.

| 데이터 | 쓰임 |
|---|---|
| HBTA 1.1, Ponte Moesa 1.1 | 개발용. 결과와 라벨을 이미 봤으므로 검증 근거가 아님 |
| LUMO 1.4 | 고정한 방법을 한 번만 시험. 고르는 동안 값을 보지 않음 |
| HBTA 1.2 확인용, Moesa 1.3, Vänersborg, Old ADA | 쓰지 않음 |
| HW 축소모형 | 최종 성능 확인 (나중) |

## 2. 후보 (8개, 실행 뒤 추가하지 않음)
| 부분 | 선택지 |
|---|---|
| 특징 (acc01·acc02, z) | F1 v1 특징 10개씩 / F2 크기 영향을 줄인 특징: crest, dom_freq, 대역 에너지 ÷ 세 대역 합 |
| 점수 (정상 대비 z-score 뒤) | M1 Isolation Forest (200, 시드 42) / M2 Ledoit–Wolf 공분산 마할라노비스 거리 |
| 묶기 (같은 실험에서 이어진 Window) | P1 최근 3개 중 두 번째로 큰 점수 / P2 최근 5개 점수의 중앙값 |

- AR·1-TAC는 AI② 지표라 쓰지 않는다. v1의 진폭 비 특징과 최대 |z| 보조 규칙을 뺐으므로 F1·M1·P1은 v1과 같지 않다.
- 온도 보정 없음. 학습은 정상 train, 임계값은 정상 val의 묶은 점수 p99.

## 3. 고르는 규칙 (`src/ai1_dev_select.py`)
1. 열화본에서 보류가 아니고 라벨이 '확실'인 Window만 쓴다. 정상 = HBTA UDS, Moesa DS2.
2. 데이터마다 정상(ai2_calib + test)과 손상 test의 AUC를 묶은 점수로 구한다. 정상 또는 손상이 30개 미만이면 그 후보는 제외.
3. 정상(ai2_calib + test) 오경보율이 두 데이터 모두 10% 이하인 후보만 남긴다 (정상 Window가 적어 5%는 가리기 어려움).
4. 남은 후보 중 두 데이터 AUC의 작은 값이 가장 큰 것. 0.02 이내면 단순한 것 (특징 F2, 점수 M2, 묶기 P1 순으로 우선).
5. 남은 후보가 없거나 작은 AUC가 0.60 미만이면 "개선 방법을 찾지 못함"으로 기록하고 LUMO 시험은 AI②와 다시 정한다.
- 원본, 손상 상태별 탐지율, 측정 단위 재표집 95% 구간은 보고만 한다. 8개 결과를 모두 보고한다.

## 4. 순서
1. 이 문서와 코드를 커밋(합성 데이터로만 점검)
2. 8개 한 번 실행
3. 고른 방법으로 LUMO 설계를 고쳐 커밋 → LUMO 1회 시험

이 커밋은 LUMO 설계 고정 커밋이 아니다.

## 5. 한계
- 라벨을 본 데이터로 후보를 만들었으므로 HBTA·Moesa 성적은 실제보다 좋게 나올 수 있다.
- HBTA는 손상 상태마다 측정이 1개라 측정 차이와 손상을 구분할 수 없다. Moesa 정상은 DS2이고 DS6·DS7은 Window가 적다.
- 교량 2개로는 일반화를 입증할 수 없다.
