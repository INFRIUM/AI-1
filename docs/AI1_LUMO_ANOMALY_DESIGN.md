# AI① LUMO 이상탐지와 AI①→AI② 연결 평가 설계

작성일: 2026-11-23 · 작성: AI① · 코드: `src/ai1_lumo.py` · AI② 보완: INFRIUM/AI-2#15 댓글 7092337355

이 문서와 코드가 커밋되면 고정이다. 결과를 보고 특징, 모델, 임계값, 묶기, 구간을 바꾸지 않는다. AI② Truss v4 사전 등록서와 1회 평가는 바꾸지 않는다.

## 1. 방법을 고른 과정
- `docs/AI1_IMPROVEMENT_PLAN.md` 규칙을 커밋(`3dbb1ed`)한 뒤 HBTA·Ponte Moesa 1.1에서 후보 8개를 한 번 실행했다. 결과는 `results/public/ai1_dev_select/`.
- 규칙대로 **F1·M2·P2**(v1 특징, 정상 기준 거리, 최근 5개 중앙값)가 뽑혔다. 열화본 AUC / 오경보 / 탐지: Moesa 0.925 / 9.9% / 85%, HBTA 0.640 / 0% / 2%. 기준(작은 AUC 0.60, 오경보 10%)을 가까스로 넘었다.
- 두 데이터는 이미 본 것이라 검증이 아니다. **LUMO 통과를 기대할 근거는 약하다.**

## 2. 데이터와 역할 (`AI1-public-1.4` LUMO, 주 평가 열화본, 원본은 원인 구분용)
| 역할 | 구간 |
|---|---|
| 학습 | `N1_B1_0803`, `N1_B1_0905` |
| 임계값 | `N1_B2_0814`, `N1_B2_0825`, `N1_B2_0916`, `N1_B2_0927` |
| 오경보 (합격 판정) | N2–N7 구간 12개 |
| 큰 손상 (합격 판정) | `DAM6_111`, `DAM4_111`, `DAM3_111` 구간 6개 |
| 보고만 | `010` 구간 6개, `N1_S_1006` |

## 3. AI① 이상탐지
| 항목 | 값 |
|---|---|
| 입력 | 센서 2개 × x·y × 10개 = 40개 (rms, std, max, min, p2p, crest, dom_freq, 대역 에너지 3개). 개발 때는 z축 20개였고 LUMO는 수평 2축이라 40개 |
| 점수 | 보류 아닌 학습 Window의 평균·표준편차로 z-score → Ledoit–Wolf 공분산 마할라노비스 거리(제곱). 온도 보정 없음 |
| Window 이상 (`ai1_window_anomaly`) | 점수 > 임계값 구간(보류 아님) p99. 참고 열 |
| 최종 이상 (`ai1_final_anomaly`) | 같은 블록에서 30초씩 이어진 보류 아닌 Window의 **최근 최대 5개 점수 중앙값** > 임계값 구간의 같은 값(3개 이상 묶인 Window) p99 |
| 5개보다 적을 때 | 있는 만큼(1개부터)의 중앙값. AI② 판정 Window에 블록의 세 번째 Window부터 들어가므로 필요. 개발 때는 5개를 모두 요구했으므로 이 점이 다르다 |
| 보류 Window | 점수는 내지만 묶지 않고 최종 이상 0. 채점하지 않음 |
| 센서 (`top_sensor`) | 센서별 20개 특징으로 같은 거리를 구해 임계값 구간 p99로 나눈 값이 큰 쪽(ML5 / ML1). 손상 위치로 해석하지 않음 |
| 판정하지 않음 | 보류 아닌 학습 또는 임계값 Window, 또는 3개 이상 묶인 임계값 Window가 200개 미만이면 결과를 내지 않고 "판정 불가"로 기록 |

출력 `lumo_ai1_predictions.csv`(열화본, 30,096행): 키 2개, `ai1_window_anomaly`, `ai1_final_anomaly`, `anomaly_score`, `pooled_score`, `pooled_n`, `max_abs_z`, `top_sensor`. 원본은 `lumo_ai1_predictions_raw.csv`. 코드는 손상 라벨 열을 읽지 않고, 값 요약을 화면에 출력하지 않는다.

## 4. 연결 평가
- 키 = `experiment_id` + `window_start_us`. 한쪽에만 있거나 중복이면 멈춘다. 분모는 AI② 등급 파일의 `judged` = True. AI② 판정 Window에 AI① 보류가 있으면 멈춘다.
- **연결 경보 = AI① 최종 이상 그리고 AI② `abnormal`(경고·위험).**

| 구분 | 항목 | 기준 |
|---|---|---|
| AI① 단독 | 오경보율 (N2–N7), 큰 손상 탐지율 (`111`) | ≤ 5%, ≥ 95% |
| AI② 단독 | v4 요약 파일 값을 옮김. 같은 분모의 재계산 값(`ai2_check`)은 일치 확인용 | v4 판정 그대로 |
| 연결 | 오경보율, 탐지율 | ≤ 5%, ≥ 95% |
| 손실 구분 (`111`) | AI①이 놓침 / AI①은 잡고 AI②가 놓침 / 둘 다 잡음 | 보고만 |
| 오경보 구분 (N2–N7) | AI①만 / AI②만 / 둘 다 | 보고만 |
| 구간별 31개, `top_sensor` 분포, 묶인 Window 수, 원본 | | 보고만 |

- 오경보와 탐지 조건을 모두 만족해야 통과. 판정 Window가 200개 미만이면 잠정.
- 원본은 열화본 판정 Window와 겹치는 것만 쓴다 (v4 8.2절). 입력 파일 MD5(LF 기준)를 출력에 기록한다.

## 5. 순서 (AI② 보완 3절)
1. AI① 이 문서·코드·합성 데이터 점검 커밋 → 2. AI② LUMO 1회 실행, SHA-256만 공개 → 3. AI① `detect` 1회, 결과 파일 커밋 → 4. AI② 결과 공개 → 5. AI① `link` 1회 → 6. AI② 재현 확인.

결과가 나오기 전에 코드가 멈추면 버그만 고치고 고친 내용을 기록한다. `detect`와 `link`는 결과 파일이 있으면 다시 실행되지 않는다.

## 6. 해석과 한계
- 해석은 AI② 보완 4절을 따른다. 연결 탐지율·오경보율은 각자의 단독 값보다 클 수 없다. 연결 결과는 v4 결과를 바꾸지 않는다.
- 진폭 특징이 바람에 따라 변하고 정상 기준이 8–9월뿐이라 계절·바람 변화를 손상으로 볼 수 있다. 이 방법은 바로 그 진폭 특징을 쓴다.
- AI①과 AI②가 같은 신호와 정상 구간을 써서 독립된 판단이 아니다. AI① 단독 비율은 "v4 판정 Window 기준"이다.
- AI①은 LUMO 라벨, Vänersborg 결과, HBTA·Moesa 결과를 알고 설계했다. LUMO 특징 값은 보지 않았으나 처리 로그에 v2 모드 진동수(원본 train 피크 3개)가 자동 출력됐다.
- LUMO는 교량이 아니라 격자 철탑이다. 교통 진동 조건의 트러스교 손상 탐지는 검증 데이터가 없고, 우리 교량의 성능은 HW 데이터로 따로 확인해야 한다.
